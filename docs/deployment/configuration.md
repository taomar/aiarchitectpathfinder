# Deployment configuration

Set values with `azd env set NAME VALUE --environment <name>`. Do not place real
values into committed Bicep or example files. The selected environment lives
under `.azure`, which is excluded from Git.

## Hosting and login

| Setting | Required value |
| --- | --- |
| `AZURE_SUBSCRIPTION_ID` | Subscription that will contain the Web App. |
| `AZURE_LOCATION` | Azure region, for example `westeurope`; an existing plan must match. |
| `AZURE_RESOURCE_GROUP` | Existing resource group; never auto-created by this template. |
| `AZURE_WEB_APP_NAME` | Globally unique app name, chosen before Entra callback registration. |
| `CREATE_APP_SERVICE_PLAN` | `true` (default) creates a single-instance B1 plan; `false` reuses a plan. |
| `AZURE_APP_SERVICE_PLAN_NAME` | Optional name for a new plan; defaults to the app name plus `-plan`. |
| `EXISTING_APP_SERVICE_PLAN_ID` | Full resource ID when reusing a plan. |
| `AUTH_MODE` | `password` or `entra`. |
| `AUTH_PASSWORD_HASH`, `AUTH_SESSION_SECRET` | Generated by the password setup command; password profile only. |
| `AUTH_ENTRA_TENANT_ID`, `AUTH_ENTRA_CLIENT_ID`, `AUTH_ENTRA_CLIENT_SECRET` | Existing Entra registration configuration; Entra profile only. |
| `ADMIN_EMAILS` | Optional explicit comma-separated administrator addresses; never grants login by itself. |
| `WORKLOAD_IDENTITY_RESOURCE_ID` | Existing user-assigned identity resource ID for managed-identity model access. |
| `APP_AI_SETTINGS` | JSON object of server-side model settings, described below. |

The template derives `APP_ORIGIN` from the actual default hostname returned by
Azure, not a guessed hostname. Custom domains are not created or configured by
this deployment.

## Existing model access

Prepare a JSON object containing only supported AI setting names:

```powershell
$modelSettings = @{
  PATHFINDER_AI_MODE = "external-foundry"
  PATHFINDER_FOUNDRY_ENDPOINT = "https://<existing-resource>.openai.azure.com/"
  PATHFINDER_FOUNDRY_AUTH = "managedIdentity"
  PATHFINDER_WIZARD_DEPLOYMENT = "<existing-wizard-deployment>"
  PATHFINDER_ARCHITECTURE_DEPLOYMENT = "<existing-architecture-deployment>"
  PATHFINDER_JUDGE_DEPLOYMENT = "<existing-judge-deployment>"
  PATHFINDER_JUDGE_REASONING_EFFORT = "medium"
  AZURE_OPENAI_ENABLED = "true"
  AZURE_CLIENT_ID = "<existing-user-assigned-identity-client-id>"
  AZURE_TENANT_ID = "<model-resource-tenant-id>"
}
azd env set WORKLOAD_IDENTITY_RESOURCE_ID "<existing-identity-resource-id>" --environment <name>
azd env set APP_AI_SETTINGS ($modelSettings | ConvertTo-Json -Compress) --environment <name>
```

Replace every placeholder. The three roles can reference the same existing
deployment if it supports their required behavior. The endpoint is the model
resource root, not a Foundry project URL. No model is deployed by this project.

The identity must already have model data-plane permissions on the existing
resource. Attaching an identity does not grant permissions. Preflight can
exercise the operator's credential before the Web App exists; model access using
the attached identity must also be verified from the deployed app.

For API-key mode, replace the authentication value with `apiKey`, omit the
identity settings, and add `AZURE_OPENAI_API_KEY` to the object using a secret
input rather than typing it into shell history:

```powershell
$secret = Read-Host "Existing model resource API key" -AsSecureString
$modelSettings.PATHFINDER_FOUNDRY_AUTH = "apiKey"
$modelSettings.Remove("AZURE_CLIENT_ID")
$modelSettings.AZURE_OPENAI_API_KEY = ConvertFrom-SecureString $secret -AsPlainText
azd env set APP_AI_SETTINGS ($modelSettings | ConvertTo-Json -Compress) --environment <name>
$modelSettings.Remove("AZURE_OPENAI_API_KEY")
```

API-key mode is useful for controlled tests and environments where a compatible
pre-authorized workload identity is unavailable. Store and rotate the key
according to your organization's policy.

## Secret handling

`APP_AI_SETTINGS`, password/session values, and the Entra client credential enter
Bicep through secure parameters and are not deployment outputs. They become
server-side App Service settings, not browser variables.

**azd environment files are local plaintext, not a secret vault.** Protect the
workstation and CI inputs. Never commit `.azure`, `.env.local`, generated
password files, logs, or deployment archives. Do not paste the output of
`azd env get-values` into tickets, guides, or chat.

## Optional capabilities

The basic profiles do not configure Cosmos usage persistence or Application
Insights. They do not inherit any administrator or tenant-specific defaults.
Shared-password users cannot open the admin dashboard.

The existing image-generation integration is optional and is not configured by
these minimal chat-model profiles. Deterministic architectural diagrams and
exports remain available; do not advertise image generation as enabled unless
an existing compatible image backend is separately configured and verified.

## Operational limitations

- Shared-password sessions expire after eight hours. Password or signing-secret
  rotation invalidates existing sessions after the updated settings are deployed.
- Simple-profile login throttling is process-local and account-wide: twenty
  attempts per fifteen minutes. The provided new plan has one instance.
  Restarts reset that limit; it is not a distributed abuse-prevention service.
  Use Entra for broader sharing or scaled deployments.
- Entra authentication is enforced by App Service. The application additionally
  checks the configured tenant and requires the platform authentication module.
  Do not run Entra mode behind a proxy that merely accepts identity headers.
- Preflight calls each distinct configured model with a synthetic prompt; those
  calls may incur small model usage charges.
- Changing `APP_AI_SETTINGS` replaces the managed model configuration. Re-run
  preflight and redeploy rather than editing generated packages.
